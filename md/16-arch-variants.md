*第十六章 · 架构变体*

# 架构变体：MoE、MLA、Mamba 与 MTP

前面所有章节都默认模型是一个稠密 Transformer。现在主流的大模型已经不是了：DeepSeek-V3 每次推理只激活 37B 参数、KV cache 只有同样规模 MHA 的 1/57，Gemma 与 Mistral 在层之间混用滑窗与全局注意力。这一章讲清楚这些变体各自改了什么、换来了什么、放弃了什么。

## 变的是哪一层

把 Transformer 块拆开，变体只动四个位置中的一两个，其余保持不变：

| 位置 | 经典做法 | 变体 |
| --- | --- | --- |
| 注意力 | 多头全注意力（MHA） | MQA / GQA / MLA / 滑窗 / 线性注意力 / SSM |
| 前馈网络 | 每个 token 过同一个 FFN | MoE：按路由激活少数专家 |
| 残差与归一化 | Pre-LN + LayerNorm | RMSNorm、QK-norm、去掉 bias、z-loss |
| 输出与训练目标 | 预测下一个 token | MTP：一次预测多个 token |

记住这张表有用：看到一个"新架构"时，先问它改的是哪一行，再问代价落在哪（显存、通信、精度，还是训练难度）。

## MoE：用同样的显存换更多参数

稠密模型的问题是参数与计算绑死：想让模型更聪明就加参数，但每加一个参数，每个 token 都要多算一次。混合专家（MoE）把 FFN 拆成 $N$ 个专家，每个 token 只走其中 $k$ 个：

$$
y = \sum_{i \in \operatorname{TopK}(x)} g_i \, E_i(x), \qquad g = \operatorname{softmax}\big(\operatorname{TopK}(x W_g)\big)\qquad (16.1)
$$

参数量按"全部专家"算，计算量按"激活的专家"算。DeepSeek-V3 是 671B 总参数、每次激活 37B；Mixtral 8×7B 是 46.7B 总参数、激活 12.9B。这就是"用同样的算力换更大的容量"的含义。

代价有三个。第一，**显存不省**：671B 的权重仍然要放进显存，只是每次只读其中一部分，所以省的是带宽和计算，不是容量。第二，**路由会失衡**：如果所有 token 都挤向同一个专家，那个专家就成了瓶颈，其余专家白占显存。训练时加一个辅助损失把负载拉平：

$$
\mathcal{L}_{\text{aux}} = \alpha \cdot N \sum_{i=1}^{N} f_i \, P_i\qquad (16.2)
$$

其中 $f_i$ 是分到专家 $i$ 的 token 比例，$P_i$ 是路由给它的平均概率。两者相乘再求和，最均衡时取最小值。第三，**通信变重**：专家分布在多张卡上时，每个 token 要 all-to-all 发到它选中的专家所在的卡，再把结果发回来——这也是 MoE 推理必须用专家并行（EP）的原因。

**DeepSeek-V3 的一次 decode：算力按激活参数算**

MoE 的 batch 越大越划算：一个 token 只激活 37B，但一次前向里不同 token 会选不同专家，合起来能把大部分专家都用上。反过来，batch 很小时只有少数专家被激活，显存里的其余专家就闲置了——这是 MoE 在低并发场景下性价比不如稠密模型的原因。

## MLA：把 KV 压成低维隐向量

第 11 章算过 KV cache 的公式 $C = 2\,L\,H_{kv}\,d\,T\,b$。GQA 靠减少 $H_{kv}$ 来省，MLA 换了个思路：**不存每头的 K 和 V，只存一份低维的隐向量**，需要时再用投影矩阵还原出各头的 K/V。

DeepSeek-V3 的做法是：每个 token 每层只缓存一个 512 维的压缩向量加 64 维的位置部分，注意力计算时再通过上投影得到 128 个头的 K 和 V：

$$
C_{\text{MLA}} = L\,(d_c + d_r)\,T\,b, \qquad d_c = 512,\; d_r = 64\qquad (16.3)
$$

代入 61 层、2 字节：$61 \times 576 \times 2 = 70{,}272$ 字节 ≈ 70 KB/token。如果同样的模型用 128 头的 MHA，每 token 每层是 $2 \times 128 \times 128 \times 2 = 65{,}536$ 字节，61 层合计约 4 MB/token——MLA 把它压到了 1/57。

| 方案 | 每 token 的 KV（同规模） | 相对 MHA | 代价 |
| --- | --- | --- | --- |
| MHA | 约 4 MB | 1× | 无 |
| MQA | 约 128 KB | 1/32 | 所有头共用 K/V，表达力下降 |
| GQA（8 组） | 约 1 MB | 1/4 | 折中方案，最常见 |
| MLA | 约 70 KB | 1/57 | 需要模型结构支持；解码时要多一次上投影 |

代价是多了一次矩阵乘（把隐向量还原成 K/V），而且这个还原要在注意力 kernel 内部完成，实现难度比 GQA 高不少。收益则直接体现在并发数上：同样一张 80 GB 卡，MLA 能挂的 128K 上下文请求是 MHA 的几十倍。

## 注意力变体地图

| 变体 | 核心改动 | 换来什么 | 放弃什么 |
| --- | --- | --- | --- |
| MQA | 所有头共享一份 K/V | KV 省 1/H | 表达力下降，长文本精度损失明显 |
| GQA | 头分成 G 组，组内共享 | KV 省 H/G，精度接近 MHA | 几乎无；现代模型的默认 |
| MLA | KV 存成低秩隐向量 | KV 省到 1/57 | 实现复杂、多一次投影 |
| 滑窗 | 只看最近 w 个位置 | 注意力计算降到 1/(T/w) | 窗口外信息看不见 |
| 线性 / SSM | 不存历史，迭代一个固定状态 | decode 与 T 无关、显存不涨 | 精确检索能力弱 |

这张表里没有"更好"的选项，只有"在什么场景下更合适"。长文档问答要精确检索，全注意力 + GQA/MLA 是主流；超长流式输入（日志、传感器）看中固定开销，线性层或滑窗更合适；而绝大多数线上服务是 8K–32K 的短上下文，GQA 就已经足够。

## Mamba 与混合模型：把"记忆"换成状态

状态空间模型（SSM，代表是 Mamba）把序列建模写成一个递推：每一步用当前输入更新一个固定大小的状态，输出由状态决定：

$$
h_t = A\,h_{t-1} + B\,x_t, \qquad y_t = C\,h_t\qquad (16.4)
$$

状态 $h$ 的大小与序列长度无关，于是 decode 的每步开销恒定、显存不随 T 增长——这是它相对 Transformer 最大的优势。代价也很直接：状态容量有限，"三个月前提到的那个人名"这类需要精确检索的信息容易丢。所以现在的做法是混合：大部分层用 SSM，少数层保留全注意力，兼顾吞吐与精度。

## MTP：一次预测多个 token

标准训练目标是"给定前文，预测下一个 token"。多 token 预测（MTP）在同一次前向里额外预测后面几个位置，训练时信号更密集，推理时这些额外输出还可以当作投机解码的草稿——第 14 章的草稿来源表里就有这一项。

$$
\mathcal{L}_{\text{MTP}} = \sum_{k=1}^{D} \lambda_k \, \mathcal{L}\big(p_\theta(x_{t+k} \mid x_{\le t})\big)\qquad (16.5)
$$

DeepSeek-V3 用 1 个额外的预测深度换到了约 1.8 倍的 decode 加速（草稿接受率不错），同时主任务的损失也更稳。代价是训练时多一份头与计算，且各深度的权重需要调。

## 归一化与激活：小改动，大影响

| 组件 | 早期 | 现在常见 | 为什么改 |
| --- | --- | --- | --- |
| 归一化 | Post-LN + LayerNorm | Pre-LN + RMSNorm | Pre-LN 梯度更稳；RMSNorm 少一次减均值，快且够用 |
| 激活 | ReLU → GELU | SwiGLU | 门控结构在同参数下效果更好（FFN 维度要相应缩小） |
| 注意力稳定 | 无 | QK-norm、z-loss、去 bias | 长训练时防止 logits 爆炸与 loss spike |
| 位置编码 | 可学习绝对位置 | RoPE（底数随长度调大） | 相对位置、可外推、不增加参数 |

## 哪些没有变

看完这些变体，容易误以为 Transformer 被换掉了。实际上四条主干一直没变：

- **自回归的语言建模目标**：给定前文预测下一个 token，损失是交叉熵。
- **decoder-only 的堆叠结构**：残差 + 归一化 + 注意力 + FFN，重复 L 层。
- **KV cache 的账**：只要还有注意力，就还有"每 token 存 K/V、decode 每步读一遍"的成本结构；MLA 只是把这个常数改小。
- **GEMM 主导**：无论是注意力的 $QK^{\top}$、$AV$，还是 FFN 的两个矩阵乘，绝大部分 FLOPs 仍然落在矩阵乘法上——这也是量化、Tensor Core、CUDA graph 这些优化能通用的原因。

> **这一章的要点**
>
> MoE 换的是"参数容量与计算量的绑定"，代价是显存与通信；MLA 换的是 KV 的存储形式，代价是一次额外的投影；滑窗与 SSM 换的是"记忆的容量与精度"，代价是精确检索能力；MTP 换的是训练的监督密度与推理的并行度。四条主干（自回归目标、decoder-only 堆叠、KV 账、GEMM 主导）没有变，所以前面十几章的分析依然成立。
